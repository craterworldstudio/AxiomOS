# ADR-0007 — Preemption Architecture, LAPIC Periodic Timer, and Bounded Ring-0 Deferral

## Status

Accepted

## Context

AxiomOS requires preemption to prevent user-space tasks from starving the system with infinite loops (`loop { pause }`). However, permitting arbitrary asynchronous preemption while executing in Ring-0 kernel mode introduces extreme complexity, concurrency hazards (re-entrant queue mutations, page table manipulation races), and requires fine-grained locking or nested interrupt stacks.

In accordance with the seL4 microkernel philosophy, the kernel must remain minimal, verifiable, and free of unnecessary policy mechanisms.

## Decision

1. **Preemption Boundary**:
   - The kernel implements **Ring-3 (User-Mode) Preemption only**.
   - Timer interrupts arriving while executing in Ring 0 acknowledge the hardware interrupt with LAPIC EOI and increment tick counters, but **defer scheduling** until a cooperative yield point (`yield_thread()`) or privilege transition back to Ring 3.

2. **Hardware Timer & Calibration**:
   - Time-slicing is driven by the Local APIC (LAPIC) periodic timer operating on IDT Vector `0x20`.
   - The LAPIC timer is dynamically calibrated at boot against PIT Channel 2 (11,932 oscillator cycles $\approx 10\text{ ms}$).
   - Legacy 8259 dual-PIC interrupts are masked (`0xFF` on ports `0x21` and `0xA1`).

3. **Dual Execution Context Models**:
   - `FrameKind::Cooperative`: 6 callee-saved registers (`rbp, rbx, r12..r15`), switched via `switch_context` and returned via `ret`.
   - `FrameKind::Interrupt`: 15 general-purpose registers (`r15..rax`) saved under the hardware `iretq` frame (`ss, rsp, rflags, cs, rip`).
   - The scheduler dynamically bridges between cooperative and interrupt frames (`switch_to_interrupt_frame` and `resume_cooperative_from_interrupt`).

4. **16-Byte Stack Alignment & Privilege Restorations**:
   - The interrupt assembly path enforces System V AMD64 ABI 16-byte stack alignment (`(RSP + 8) % 16 == 0` upon entry).
   - When returning to Ring 3 via `iretq`, user data segment selectors (`DS` and `ES`) are explicitly reloaded with `0x1B` without clobbering `RAX`.

5. **Dynamic TSS RSP0 Synchronization**:
   - On every scheduling transition, `TSS.privilege_stack_table[0]` (`RSP0`) is updated to the incoming thread's private kernel stack (`stack_base + PAGE_SIZE`).

## Bounded Execution Latency Guarantees

Because all Ring-0 microkernel primitives (`retype`, `endpoint_send`, `endpoint_receive`, `yield_thread`, `map_page`) execute in bounded $O(1)$ time ($< 2\,\mu\text{s}$):
- Worst-case preemption deferral latency is strictly bounded to $< 5\,\mu\text{s}$.
- Kernel data structures (`SCHEDULER`, `KERNEL_OBJECT_TABLE`, `GENESIS_CNODE`, `BitmapAllocator`) are immune to preemption races without requiring re-entrant kernel spinlocks.
