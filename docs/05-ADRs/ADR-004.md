# ADR-0004 — Untyped Memory and Retyping

## Status

Accepted

## Context

The kernel requires memory to store kernel objects such as TCBs, CNodes, VSpaces, and Endpoints.

A traditional kernel heap would introduce implicit kernel resource consumption. It would also make accounting and authority over kernel-object creation less explicit.

The kernel cannot request memory from userspace while simultaneously depending on that memory to perform the request.

This creates a bootstrap paradox.

## Decision

Physical memory available for kernel-object creation is exposed through `Untyped` capabilities.

Genesis initially receives authority over the available untyped physical-memory regions.

Userspace creates kernel objects by invoking an Untyped capability with a `Retype` operation:

```text
Retype(untyped, object_type, destination)
```

The kernel validates the authority, partitions the authorized untyped region, initializes the requested kernel object, and creates a capability referring to the new object.

## Invariants

* The kernel does not use a general-purpose dynamic heap for kernel-object creation.
* Kernel objects are backed by explicitly authorized physical memory.
* Userspace determines which authorized untyped region is consumed.
* Userspace never receives direct pointers to kernel object state.
* An untyped region cannot be simultaneously used as backing storage for multiple incompatible objects.
* Kernel object creation is always capability-mediated.

## Consequences

### Easier

* Explicit accounting of kernel-object resources.
* Resource authority follows physical-memory authority.
* Genesis does not require implicit root privileges.
* Userspace can construct its own resource-management policies.

### Harder

* Userspace must track untyped memory.
* Object creation requires explicit resource management.
* Fragmentation and retyping constraints become part of the memory-management design.

## Alternatives Considered

### Kernel-managed Heap

Rejected as the primary kernel-object allocation mechanism.

A hidden kernel heap would obscure resource consumption and make it harder to express object-creation authority through capabilities.

## Relationship to Axiom 0

Untyped memory represents physical authority that can be delegated and subdivided.

Retyping transforms that resource authority into authority over specific kernel objects.

## Implementation Boundary

### Kernel

* Validate Untyped authority.
* Validate retyping parameters.
* Partition physical memory.
* Initialize kernel objects.
* Create the resulting capability.
* Maintain object-allocation invariants.

### Userspace

* Track available Untyped regions.
* Decide which objects should be created.
* Decide where those objects should be placed.
* Delegate resulting capabilities.

## Future Reconsideration

This decision may be amended for architectures requiring special preallocated regions or hardware-specific object pools.

Such mechanisms must preserve explicit authority and accounting.
