# ADR-013 — Sovereign Partition Table, Continual Block Storage, and Emergency Panic Substrate

## Status

Accepted (Phase 8 Baseline Implemented; Phase 8.5 Continual Storage Planned)

## Context

Following the completion of the Sovereign Namespace and initial ATA PIO persistence in Phase 8, two critical operational and architectural requirements emerged:
1. **System Diagnostics, Shell Usability & Resiliency**:
   - The OS needed standardized command introspection (`-h` / `--help`) across all standalone C, Assembly, and built-in commands.
   - Non-executable files typed into the shell previously attempted execution at `0x500000`, causing CPU faults.
   - Machine power-down lacked a hardware-level ACPI shutdown pathway.
   - A Kernel Panic froze the machine into an unrecoverable halt loop, requiring manual hypervisor process termination without an interactive bare-metal reset vector.
2. **Continual Persistent Storage Constraints**:
   - The Phase 8 ATA PIO storage driver proved reboot persistence using a static 512-byte `DiskSuperblock` mapped to `target/axiom_data.img`.
   - However, this initial prototype is bounded to **8 files** of **1024 bytes maximum** per file, with fixed 2-sector contiguous LBA offsets (`LBA 1 + idx*2`).
   - The system requires **continual storage space**: real disk partitioning (GPT / MBR), dynamic free block allocation, and multi-extent block chaining to support files of arbitrary size across megabyte and gigabyte storage devices.

---

## Decision

### 1. Diagnostic Resiliency & Shell Hardening (Phase 8)
- **Universal `-h` / `--help` Protocol**:
  - Implemented across all standalone binaries (`cat.c`, `ls.c`, `echo.c`, `axe.c`, `whoami.asm`) and Genesis built-ins (`cd`, `pwd`, `clear`, `reboot`, `shutdown`, `kpanic`, `status`, `curr`, `help`).
  - Genesis argument parser explicitly isolates `-h` and `--help` flags, preventing path resolution collisions.
- **Non-Executable CLI Guard**:
  - Unqualified command names are strictly resolved against `apps/sys/`. Local paths (`./a.txt`) enforce `RIGHTS_EXEC` and reject non-executable extensions (`.txt`, `.md`, `.sys`, `.ledger`), returning `Permission denied (not executable)`.
- **Clean ACPI Shutdown**:
  - Added `OP_SYS_SHUTDOWN = 31` capability syscall dispatching PM1a_CNT poweroff sequences (`0x604:0x2000`, `0xB004:0x2000`, `0x4004:0x3400`, `0x600:0x2000`) in Ring 0.
- **Emergency Panic Reboot State Machine**:
  - In `axiom_kernel/src/console.rs`, `panic_emergency_reboot_loop` polls PS/2 ports `0x64` / `0x60` bare-metal with interrupts disabled (`cli`) and zero dynamic heap allocations.
  - Detects `Ctrl+Shift+Alt` make codes to arm the emergency sequence.
  - Tracks sequential make scancodes for `R-E-S-E-T` and `Enter`, updating an on-screen status line in real-time.
  - Cascades 4 reset mechanisms upon confirmation: 8042 controller pulse (`outb 0x64, 0xFE`), PCI reset (`outb 0xCF9, 0x06`), ACPI reset (`outw 0x604, 0x2000`), and IDTR null triple-fault fallback.

### 2. Continual Storage Architecture & Partitioning (Phase 8.5)
- **Partition Table Substrate**:
  - The raw disk endpoint `edps/drives/ata0` (Slot 7) will host a GPT / MBR partition parser.
  - Each detected partition is registered as a scoped child endpoint (e.g., `edps/drives/ata0p1`, `edps/drives/ata0p2`).
  - Derived partition capabilities enforce LBA boundary clamping: $LBA_{\text{start}} \le LBA < LBA_{\text{start}} + \text{SectorCount}$. A process holding a partition capability cannot read or write outside its allocated slice.
- **Continual Extent-Based Block Allocation**:
  - **Free Block Bitmap**: Sector 1..$N$ store a bitmask of allocated/free disk clusters.
  - **Dynamic Inodes & Extent Descriptors**: Files are represented by inodes containing a list of `(start_lba, sector_count)` extents, allowing non-contiguous and dynamically growing storage allocations up to disk capacity.
  - **Dynamic Directory Inodes**: Directory maps become dynamically allocated on-disk inode blocks, removing the in-memory `MAX_NODES` ceiling.
- **In-Memory Block Buffer Cache**:
  - A userland LRU cache layer prevents redundant synchronous ATA PIO disk round-trips.
- **Future DMA Migration**:
  - Provide a migration path from 16-bit PIO to PCI AHCI Bus Master DMA for high-bandwidth disk operations.

---

## Consequences

- **Positive**: AxiomOS can recover from catastrophic substrate failures directly from the physical keyboard without hard host resets.
- **Positive**: Every system command provides self-documenting usage guides adhering to consistent visual design standards.
- **Positive**: Storage moves from a static 8-slot prototype to an industrial, scalable extent-based block filesystem with real partition tables.
- **Operational Requirement**: Phase 8.5 must implement the Free Block Bitmap and Extent Inode structure in `libaxiom/src/fs.rs` alongside disk image expansion scripts in `build.sh`.
