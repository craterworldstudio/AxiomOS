ADR-0003 — Kernel vs. Userspace Boundary

Status

Accepted

Context

Axiom requires a strict separation between mechanisms required for isolation and policy implemented by operating-system services.

Including filesystems, network stacks, device drivers, or other high-level services inside the kernel would enlarge the trusted computing base and make independent userspace environments dependent on kernel implementation details.

Decision

The kernel is the trusted authority and isolation mechanism.

The initial kernel owns exactly five primitive object families:

Thread Control Blocks (TCB)

Virtual Address Spaces (VSpace)

Capability Spaces (CNode)

IPC Endpoints (Endpoint)

Untyped Memory (Untyped)

Everything else is constructed in userspace from these primitives.

Invariants

The kernel contains no filesystem implementation.

The kernel contains no TCP/IP implementation.

The kernel contains no device-driver implementation.

The kernel contains no userspace process manager.

The kernel does not contain a built-in demand pager.

Page faults are exposed to an authorized userspace pager through a kernel-mediated mechanism.

Hardware isolation and privilege boundaries remain kernel responsibilities.

Consequences

Easier

Small trusted computing base.

Independent userspace services.

Distro neutrality.

Easier auditing and eventual formal verification.

Services can be replaced without changing the kernel.

Harder

IPC becomes fundamental to system performance.

Page faults and device operations may cross userspace/kernel boundaries.

Userspace must implement services traditionally found inside monolithic kernels.

Alternatives Considered

Monolithic Kernel

Rejected as the primary architecture.

A monolithic kernel would place drivers, filesystems, networking, and other policy-heavy services inside the trusted computing base.

Kernel Pager

Rejected as the default architecture.

Memory-management policy belongs in userspace so that different operating-system environments can implement different paging policies.

Relationship to Axiom 0

The kernel is the mechanism that enforces capability authority.

The higher-level authority graph and service architecture are constructed through capability delegation rather than through a privileged kernel namespace.

Implementation Boundary

Future Reconsideration

This boundary may be reconsidered if future hardware fundamentally changes the mechanisms required for isolation, or if Axiom's capability architecture is replaced.
