# ADR-0008 — Hardware Fast-Path Syscall Gateway, Capability Derivation Tree (CDT), Atomic RPC, and Kernel Boundary Freeze

## Status

Accepted (Microkernel Boundary Frozen)

## Context

AxiomOS has achieved full functional maturity as a sovereign microkernel (Phases 1 through 4). To support user-mode execution environments, compilers, and user-space operating system servers (Phase 6+), the microkernel ABI must transition from software trap interrupts (`int 0x80`) to the standard x86-64 hardware fast-path (`syscall` / `sysretq`) with strict kernel stack isolation. 

Furthermore, a true object capability system requires:
1. **Rights monotonicity**: A child capability can never possess rights not held by its parent ($R_{\text{child}} \subseteq R_{\text{parent}}$).
2. **Recursive transitive revocation**: Revoking authority from a capability must recursively invalidate all transitive derivations down the Capability Derivation Tree (CDT).
3. **Atomic synchronous RPC**: Client-server IPC requires an atomic send-and-block-receive rendezvous primitive (`OP_CALL`) with timeslice handover.
4. **Kernel security hardening**: Complete mitigation of CPU speculative execution side-channels (Spectre v1), SYSRET non-canonical vulnerabilities (CVE-2012-0217), and kernel register information leaks.

## Decision

1. **Hardware Fast-Path System Call Gateway**:
   - Programmed x86 MSRs:
     - `IA32_EFER` (`0xC000_0080`): Bit 0 (SCE - System Call Extensions) enabled.
     - `IA32_STAR` (`0xC000_0081`): Bits 47:32 Kernel CS `0x08`, Bits 63:48 User Base `0x10`.
     - `IA32_LSTAR` (`0xC000_0082`): Bound to `syscall_entry`.
     - `IA32_SFMASK` (`0xC000_0084`): Value `0x47700` automatically masks `IF`, `DF`, `TF`, `AC`, `NT`, `IOPL`.
     - `IA32_KERNEL_GS_BASE` (`0xC000_0102`): Bound to per-CPU data structure `CpuLocal`.
   - Atomic stack isolation via `swapgs`: Untrusted user `RSP` is stored in `gs:[0]`, and trusted thread kernel stack is loaded from `gs:[8]` before pushing any registers onto the stack.

2. **Calling Convention and Register Sanitization**:
   - System call arguments: `RDI` (handle), `RSI` (operation), `RDX` (arg1), `R10` (arg2, forwarded to `RCX`), `R8` (arg3), `R9` (arg4).
   - Scratch register sanitization: Scratch registers (`RDI`, `RSI`, `RDX`, `R8`, `R9`, `R10`) are zeroed before executing `sysretq`, preventing kernel stack or pointer leaks.
   - User segment reload: Data segments (`DS`, `ES`) are reloaded with `0x1B` via `R10W` prior to `sysretq`.

3. **Security Hardening**:
   - **Spectre v1 Barrier**: Bounds check on capability handle index is immediately followed by `lfence` to halt speculative execution.
   - **SYSRET Non-Canonical Address Defense (CVE-2012-0217)**: `RCX` (user `RIP`) is verified to be a canonical user address (`RCX < 0x0000800000000000`) before popping user `RSP` or executing `sysretq`.
   - **Stack Isolation**: Kernel stacks are isolated to per-thread dedicated 4 KiB frames; user mode cannot tamper with kernel stack frames.

4. **Capability Derivation Tree (CDT)**:
   - Capability slots track derivation links (`parent`, `first_child`, `next_sibling`, `prev_sibling`).
   - `OP_MINT`: Monotonically derives an attenuated capability into a destination slot. Escalation attempts are rejected with `ERR_INVALID_RIGHTS`.
   - `OP_REVOKE`: Recursively invalidates all descendant capabilities in the derivation subtree, advancing generation counters to instantly invalidate in-flight handles (`ERR_STALE_HANDLE`), while preserving the parent capability.
   - `OP_DELETE`: Recursively revokes descendants and safely unlinks the slot from the parent and sibling lists.

5. **Atomic RPC Primitive (`OP_CALL`) & Direct Timeslice Handover**:
   - `OP_CALL` delivers a message payload to a waiting receiver on an Endpoint and atomically transitions the calling thread to `ThreadState::BlockedReceive`.
   - The scheduler implements `enqueue_front(receiver_ref)`, performing direct timeslice donation to the server thread for bounded RPC latency.

6. **Microkernel Boundary Freeze**:
   - Ring 0 kernel mechanisms are formally complete and frozen.
   - No further user abstractions, filesystem drivers, or shell logic will reside in Ring 0. All future development (shell, memory allocators, C/ASM toolchains, login services) will execute in isolated Ring 3 user tasks.
