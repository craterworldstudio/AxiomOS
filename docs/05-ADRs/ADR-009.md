# ADR-0009 — The Genesis Process (PID 1) and User-Space Capability Runtime (`libaxiom`)

## Status

Accepted (Phase 6 Milestone Verified)

## Context

With Phase 5 formally freezing the Ring 0 microkernel boundary, the operating system requires an isolated, foundational user-space environment to coordinate system services. In traditional Unix, the init process (`PID 1`) relies on POSIX system calls provided directly by a monolithic kernel. In a pure object-capability microkernel, `PID 1` (the Genesis Process) must execute in Ring 3 ($CPL=3$), hold only explicit capability references in a private capability space (CSpace), and coordinate user-mode services without ambient privilege.

To achieve this without duplicating kernel code or bringing in standard library overhead:
1. Legacy `axiom_core` must be decoupled from the kernel build tree and archived.
2. A lightweight, pure `#![no_std]` capability runtime crate (`libaxiom`) must be created to provide safe Rust capability wrappers and system call invocation primitives.
3. The root user process (`axiom_genesis`) must be independently compiled, linked at virtual address `0x400000`, and dynamically loaded into a dedicated virtual address space (VSpace).
4. The kernel must verify complete privilege isolation: user-mode reads of supervisor pages must trigger hardware Page Faults (`#PF`, Vector 14) that safely terminate the faulting thread without destabilizing the kernel.

## Decision

1. **Decoupling and Archiving `axiom_core`**:
   - `axiom_core` was moved to `archive/axiom_core` and removed from the active workspace `Cargo.toml`.
   - Replaced by two dedicated `#![no_std]` crates:
     - `libaxiom`: The user-space capability runtime and system call abstraction layer.
     - `axiom_genesis`: The root Genesis user task executing as PID 1.

2. **The `libaxiom` Capability Runtime Architecture**:
   - **Syscall Gateway (`libaxiom/src/syscall.rs`)**:
     Implements hardware `syscall` inline assembly conforming to System V AMD64 calling conventions (`RDI`, `RSI`, `RDX`, `R10`, `R8`, `R9`) with clobber protection for `RCX` and `R11`.
   - **Strongly Typed Capabilities (`libaxiom/src/capability.rs`)**:
     Defines `CapHandle`, `Rights`, `ObjectKind`, and typed wrapper structs (`EndpointCap`, `CNodeCap`, `UntypedCap`).
   - **Synchronous IPC (`libaxiom/src/ipc.rs`)**:
     Provides high-level helpers for synchronous capability operations: `rpc_call`, `ipc_send`, `ipc_recv`.
   - **User-Space Memory Allocator (`libaxiom/src/allocator.rs`)**:
     Provides a lock-free `BumpAllocator` implementing `core::alloc::GlobalAlloc` to enable standard Rust collections (`alloc`) in Ring 3 if needed.
   - **Console Driver (`libaxiom/src/console.rs`)**:
     Provides capability-backed printing primitives implementing `core::fmt::Write`, exposing `print!` and `println!` macros in user space.

3. **Dual Linker Script Architecture**:
   - Kernel and user binaries have separate virtual address bases:
     - Microkernel: Linked at physical/virtual base `0x100000` via `axiom_kernel/build.rs`.
     - Genesis Process: Linked at virtual base `0x400000` via `axiom_genesis/build.rs` and `axiom_genesis/linker.ld`.
   - Removed `-C link-arg=-Tlinker.ld` from `.cargo/config.toml` to prevent linker flag contamination across crates.

4. **Dynamic Multi-Page Binary Loading (`main_prod.rs`)**:
   - Rather than assuming a fixed size, the kernel calculates `num_pages = (bin_len + 4095) / 4096`.
   - Physical frames are dynamically allocated from `BitmapAllocator` and mapped contiguously into the Genesis VSpace starting at `0x400000` with `PRESENT | USER | WRITABLE` flags.
   - Data and stack pages are mapped separately: Mailbox/progress page at `0x408000`, user stack at `0x800000`.

5. **Root Capability Namespace (CSpace)**:
   - Genesis is allocated a private `CNode` containing root capabilities:
     - Slot 1: Root `CNode` capability (`Rights::ALL`).
     - Slot 2: Root `VSpace` capability (`Rights::ALL`).
     - Slot 3: Root `TCB` capability (`Rights::ALL`).
     - Slot 5: Root `Console` Endpoint capability (`Rights::ALL`).

## Consequences

- **Positive**: Complete architectural separation between kernel mechanisms and user-space policy.
- **Positive**: Genesis runs in pure Ring 3 ($CPL=3$) under strict memory and capability isolation.
- **Positive**: Verified by 54 automated boot self-tests in emerald green (`gallery/Phase6GenesisProcessVerified.png`).
- **Care Requirement**: Retyped `CNode` memory must be explicitly initialized with `CNode::new()` so that generational counters default to 1, avoiding false `ERR_STALE_HANDLE` rejections.
